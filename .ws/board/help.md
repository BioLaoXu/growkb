# ControlTower 工作流全解（帮助文档）

> 本文档由看板**实时读取**：编辑 `.ws/board/help.md` 并保存，重新打开帮助即为最新内容，无需任何生成步骤。

## 一、总览：一个任务的一生

| 环节 | 底层动作 | 触发方式 | 产出 |
|---|---|---|---|
| ① 投递（建卡） | 卡文件写入 `.inbox/` | 工作台 scp / `ws_dispatch` / 看板 ➕ 新建 | 信息卡 |
| ② 受理 | 核验卡 + 建项目/任务（如未建）+ 写 accepted 回执 | 看板 [受理] / Agent 会话「受理 …」 | 任务目录 + 回执 |
| ③ 开工 | `status: planned → wip`，按需求做分析 | CodeBuddy 开工会话 | scripts/ + results/ |
| ④ 收尾 | 补 methods/scripts/output，`status: done`，写 done 回执 | 收尾会话 | 可检索的任务记录 |
| ⑤ 交付 | 打包（排除软链/元数据）+ 写 delivered 回执 | 看板 [打包+交付] | tar.gz 交付包 |
| ⑥ 同步生产 | `ws_deliver.sh -y` 并入生产目录 | 需要时执行 | 生产 Analysis/ 更新 |

**受理的底层逻辑**：受理 = 写一份"接单声明"（`.outbox/…accepted.yaml` 回执），仅此而已 ——
它**不建任务**（建任务在②中另有动作）、**不跑分析**、**不改任务状态**。回执的作用是让工作台（pwb）
对账时知道"投出的单已被服务器接下"。

## 二、两种投递语义

| 语义 | 命令 | 行为 |
|---|---|---|
| 投递即受理（默认） | `ws_dispatch.sh -b 批次 -p 产品 -s 目录 -r 需求` | 建项目+建任务+写卡一步完成；任务直接进总表（planned）；卡瞬时归档 |
| 卡-only（谨慎模式） | 同上 + `-C` | 只写卡到 `.inbox/`，任务**不创建**；总表不会出现；点卡的 [受理] 时才建 |

选择建议：自己确认过的需求用默认（快）；需要留一道人工确认关的用 `-C`。

## 三、任务状态机

| 状态 | 含义 | 允许的看板操作 |
|---|---|---|
| planned | 已建未开工 | [受理](无回执时) · [改状态] · [改需求] · [删除→回收站] |
| wip | 分析进行中 | [改状态] · [改需求] · [打包+交付] |
| blocked | 受阻待定 | 同 wip |
| done | 分析完成未交付 | [打包+交付] · [改状态] |
| delivered | 已交付 | 只读（重做请复制目录加 -v2） |

状态流转 = 改 `.meta.yaml` 的 `status` 字段（看板 [改状态] 或会话内改），每次流转建议伴随回执。

## 四、收件箱语义

- `.inbox/*.yaml`（根目录平铺）＝ **未受理**的请求，等待 [受理]
- `.inbox/accepted/` ＝ 已受理归档（两种来源：看板受理即时归档；会话受理由**对账**自动归档）
- `.inbox/ignored/` ＝ 已忽略（如重复投递的旧卡）
- **对账规则**：扫描时若卡的"批次+slug"能匹配到磁盘上已存在的任务 → 视为已受理，自动归档

**收件箱为空的常见原因**：① 所有卡都已受理归档（正常）；② 用 dispatch 投递的（投递即建任务，不经过收件箱）；
③ 投递根本没到达服务器（`scp` 目标是否为 `/data/Agent/xufa/workspace/.inbox/`）。

## 五、删除与回收站

- 看板 [删除] 仅对 **planned** 任务开放（wip/done/delivered 拒绝，防止误删成果）
- 删除 = 移入 `.trash/<时间戳>_<任务名>`（**不是真删**），同时记录原始路径（`.origin`）
- [找回] = 移回原路径（原路径被占用则报错）；[彻底删除] = 需输入 DELETE，永久移除
- 删除前建议跑一次 `bash .ws/bin/ws_backup.sh`（元数据备份，KB 级秒级）

## 六、回执与对账（pwb 协议）

- 回执文件：`.outbox/<日期>_<taskId>_<status>.yaml`（accepted/done/delivered 三种）
- 工作台按 `contractNo + batch + taskId` 对齐更新本地状态
- 看板总表的 **✓ 已受理** 徽标即来自回执反查（`.outbox` 中存在该任务的 accepted 回执）

## 七、常见问题（FAQ）

**Q：总表里没有 [受理] 按钮？**
A：① 已写过受理回执（显示 ✓ 已受理）；② 状态不是 planned。受理回执已存在的任务无需重复受理。

**Q：点 [受理] 后卡消失了？**
A：正常 —— 受理成功后卡自动归档到 `.inbox/accepted/`，任务在总表。

**Q：任务总表行数很多？**
A：顶部状态筛选 + 关键词搜索，每页 15 行分页。

**Q：删除的任务去哪了？**
A：`.trash/` 回收站，看板底部🗑区块可找回或彻底删除。

**Q：看板打不开？**
A：服务挂了跑 `bash .ws/bin/ws_board.sh restart`（cron 每 5 分钟也会自愈）；
居家访问用 SSH 隧道 `ssh -N -L 18792:127.0.0.1:8792 xufa@<服务器>` 后开 `http://localhost:18792/.ws/board/index.html`。
