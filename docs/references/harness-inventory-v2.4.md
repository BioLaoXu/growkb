# Harness 清单（人话版 v2.4，2026-11-01）

> **Harness 是什么**：包裹在大模型外面的整套"执行装备"——提示词、流程、工具、记忆、护栏。
> 模型是发动机，Harness 是整辆车。本清单逐件列出我们车上有什么、装在哪、什么时候用。
> 所有路径都可点开验证；看不懂的术语查文末"黑话表"。

## 一、提示词（Agent 每次干活"看到"的东西）

### 1. 常驻规则 `.codebuddy/rules/workspace-convention.md`
**什么时候生效**：每一次会话，自动加载，不用你做任何事。
**里面有什么**：落盘归属（什么放哪）、命名规范、任务五态状态机、受理协议（含环境预核验、
收尾封印 seal、MEMEX 纪律）、禁止事项（不猜需求/不覆盖产物/不伪造回执）。
**现状**：全文偏长（专家意见 #1：将瘦身到微内核 + 按阶段挂载，已排期）。

### 2. SessionStart 哨兵 `.codebuddy/hooks/check_inbox.py`
**什么时候生效**：每次打开新会话/新窗口，自动跑一次。
**做什么**：只注入**一行计数**——"收件箱待受理 N 条 · 进行中 M 个"，不展开卡内容
（防止续跑会话被新任务带偏，专家意见 #2）。你说「查看收件箱」或「受理」时 Agent 才展开详情。

### 3. 命名建议 Hook `.codebuddy/hooks/suggest_title.py`
**什么时候生效**：你发出首条任务相关消息（含任务路径或「受理 批次号」）时自动跑一次。
**做什么**：从消息里提取批次/合同/日期，给出会话命名建议（格式：批次_合同号_日期），
你复制到历史记录重命名即可。

### 4. 阶段门控 SOP `.ws/prompts/stage_accept.md` / `stage_wip.md` / `stage_report.md`
**什么时候生效**：任务状态切换（受理→开工→收尾）时，由 ws_meta 的 seal/patch 回显对应 SOP。
**里面有什么**：每个阶段的操作手册——受理怎么核验、开工怎么用方案库和记忆检索、
收尾怎么做证据键校验和双门禁交卷（专家 v3.5 提供，含正反例）。

### 5. 任务内三件套（开工时 Agent 自己组装进提示词）
- **plan.md**（模板 `.ws/templates/plan.md.tmpl`）：勾选清单，3-7 项，单次只许完成一项，防谎报
- **.env_check.yaml**：受理时自动核验的环境清单（生产目录存在性/样本表/config/坏软链/0 字节文件/上游指纹）
- **黄金实践段**（`.kb/docs/methods/ngs-golden-practices.md`）：NGS 通用纪律（只引生产结果不重算、
  大表只取图、结论挂证据键等），按产品线勾选适用项

## 二、流程（一个任务从生到死的路）

```
投递 ──→ 受理 ──→ 开工 ──→ 收尾 ──→ 交付
(建卡)    (接单+建任务)  (wip)   (done+封印)  (delivered)
```

| 步骤 | 谁做 | 用什么 | 产出 |
|---|---|---|---|
| ① 投递 | 你/工作台/脚本 | ws_dispatch（三通道：服务器命令行/工作台 scp/对话粘贴） | 信息卡进 .inbox/ |
| ② 受理 | Agent（会话说「受理」）或看板 [受理] | ws_new_project/new_task（如缺）+ ws_receipt + 环境预核验 | 任务目录 + .env_check.yaml + accepted 回执 + 卡归档 |
| ③ 开工 | Agent（说「继续 <任务路径>」） | plan.md 勾选清单 + 方案库 SKILL.md + 记忆检索 | scripts/ + results/ + status=wip |
| ④ 收尾 | Agent | report.md（证据键）+ 自评评分 + ws_meta seal 封印 | status=done + 产物只读 + 知识快照 + done 回执 |
| ⑤ 交付 | 你（看板点 [打包+交付]） | ws_pack + ws_receipt delivered | tar.gz 交付包 |

**两个特殊机制**：
- **收件箱对账归档**：扫描时若卡的批次+slug 能匹配到已存在任务 → 视为已受理自动归档
  （曾因只按 slug 匹配误归档过，已改双匹配）
- **两阶段受理**：投递默认"即建任务"（快）；`ws_dispatch -C` 只投卡不建任务（确认后才建，控）

## 四、记忆（MEMEX：放经验的仓库）

**位置**：.kb/memory/（正式）+ .kb/memory/.staging/（暂存）+ .superseded/（被替代的历史）
**格式**：每条经验一个 YAML，十字段（人话解释）：

| 字段 | 人话 |
|---|---|
| id | 编号（mem-日期-序号） |
| type | 类型：knowhow（怎么做）/ pitfall（踩过的坑）/ preference（偏好）/ reference（参考） |
| scope | 适用范围（哪个产品线/任务类型/global） |
| task | 从哪个任务提炼的（可溯源） |
| trigger | 什么时候该想起这条（检索关键词） |
| content | 经验本体 |
| evidence | 依据（文献/文档/先例——保证"有据"） |
| superseded | 被哪条替代（冲突时旧条目不删留痕） |
| hits | 被检索采用次数（越有用越靠前） |
| expiration | 过期日（到期读取时隐藏，不物理删） |

**现有 3 条**（都是真实事故沉淀）：
1. 批次号要纯 ASCII（中文目录名有兼容风险）——来自 ATAC 批次转写
2. 收件箱对账必须"批次+slug 双匹配"——来自误归档事故
3. 报告结论必须挂证据键——来自证据键协议

**怎么运转**：任务收尾提炼 0-3 条 → add 进暂存 → promote 转正 →
开工时 ws_memory search 按关键词检索（自动计 hits）→ 同类 ≥3 条自动提示"升华"成正式方案文档。
**防垃圾机制**：MD5 精确去重 + 语义相似度 0.85 拒绝 + knowhow 禁止带具体批次号/日期 +
矛盾删除必须写原因 + 到期自动隐藏。

## 六、评测（胶囊基准）与看板

**胶囊基准**（.bench/capsules/）：把已完成任务变成考试题——
- pack：拷贝该任务的数据表/图（**不带结论**）+ 任务书（需求原文+标准产物清单）
- 考法：让 Agent 只看数据写报告 → grade 按"标准产物覆盖率 70% + 证据键格式 30%"打分
- 现有 1 个胶囊（ATAC 数据报告）；攒够 5 个后启用 RRSI 外环自动进化
- 防作弊设计：胶囊内没有标准答案；未来加"Agent 机器不许跑被测项目"隔离

**看板**（127.0.0.1:8792）：任务总表（筛选/搜索/分页）· 待受理卡 [受理][忽略] ·
行内 [受理][改状态][改需求][删除→回收站][打包交付] · 回收站管理 · 📖帮助文档（实时读 help.md）·
cron 每 5 分钟守护自愈

**对接面**：.inbox/（待受理→accepted/→ignored/）· .outbox/（三态回执给工作台对账）·
信息卡字段映射（contractNo→contract 等）· 对账键 = 合同号+批次+任务号

## 七、有没有复用公共的知识库或 skill？（诚实回答）

**运行时：零依赖公共知识库/技能**——系统完全自包含，所有方法/经验/工具都是自己的。
这是刻意的：生信交付要求可追溯，外部黑盒技能不可审计。

**设计层：深度吸收了 33 个外部项目的范式**（但一行代码都没抄）：
SKILL.md 格式学 OmicsClaw、角色分工学 GenoAgent/CellAgent、记忆 schema 学 mem0、
评分梯度学 BixBench/GenoTEX、事件契约学 OpenHands、工具目录表学 BioMCP——
对照表见 absorb/SYNTHESIS.md（同目录）。

**未来可能的接入点**（已在路线图）：nf-core 标准管线调用、BioMCP 式文献数据源、
MCP 协议把 ws_* 工具暴露给任意 Agent、合成式记忆（MemT 路线，远期观察）。

## 八、黑话表

| 黑话 | 人话 |
|---|---|
| 信息卡 | 结构化的任务申请单（YAML：批次/合同/产品/需求/数据位置） |
| 受理 | 接单：核验申请单 + 建任务目录（如未建）+ 写"我接了"的回执 |
| 封印（seal） | 收尾动作：任务置 done + 报告表图设只读 + 记录当时知识库版本 |
| 证据键 | 结论句尾的"(文件名#表号)"标记——保证每句话有出处 |
| 胶囊 | 从已完成任务打包出的"考题"（数据+任务书，无答案），用于给 Agent 模拟考 |
| 派生视图 | 从元数据算出来的索引/看板——删了能重建，不算真数据 |
| 升华 | 3 条以上同类小经验合并成一篇正式方法文档 |
| staging/promote | 经验的"暂存区→正式区"两步走，防垃圾直接进正式库 |
| 对账归档 | 扫描时发现"卡对应的任务已存在"→ 自动把卡移入已受理归档 |
