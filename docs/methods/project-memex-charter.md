# Project MEMEX —— 知识记忆体引擎（立项书）

> 命名致敬 Vannevar Bush 1945 年提出的 **Memex**（记忆扩展设备）：一个"把人的全部书籍、记录与通信机械化，
> 并以联想轨迹相互连接"的装置 —— 正是本项目 `.kb/` 知识库想成为的东西。
> 状态：**规划完成，待启动**（2026-10-29 立项）。关联：ROADMAP P1/P5、`agent-deep-dive-2026.md`

## 一、为什么单独立项（用户指出的盲区，补挖结论）

首轮调研聚焦"分析型智能体"，知识库/记忆方向只浅尝辄止。补挖后发现：**Agent 记忆层已是一个独立的成熟赛道**，
有多套可直接借鉴的记忆组织与检索范式：

| 项目 | 星(约) | 记忆组织 | 检索方式 | 可借鉴点 |
|---|---|---|---|---|
| **claude-mem** | 100k | 压缩会话记忆，跨会话持久 | 上下文内检索 | 「会话结束→压缩→入库」的自动沉淀节奏 |
| **Mem0** | 67k | 三层作用域（user/session/agent）+ 混合存储（向量+图+KV） | 单次提取+多信号检索（语义+BM25+实体） | **事实冲突时编辑而非追加**——保持记忆精简 |
| **Hindsight** | 52k | 四层仿生结构 + 观察整合 + 心智模型 | 四路并行召回 + RRF 重排 | 「观察→心智模型」的升华路径（原始记录→规律） |
| **Letta**（原 MemGPT） | 30k | 核心记忆/回忆记忆/归档记忆三层，Agent 自编辑 | 上下文内 + 归档检索 | 分层记忆：热（当前任务）/温（项目）/冷（历史） |
| **Cognee** | 32k | 实体-关系-事件知识图谱 + 双时间轴 | 图遍历 + 语义混合 | 把"任务-方法-结果-文献"连成图谱 |
| **Biomni Know-How** | 4.0k | 结构化经验条目库（任务类型→成功方案→坑） | 智能体规划时检索 | ★ 条目化经验库的直接同构物 |
| **BioMedAgent**（Nature BME） | — | `SAVE_MEMORY/USE_MEMORY`：成功任务经验结构化存储 + 跨任务检索 | tool-aware 经验检索 | ★ RSI 记忆体的完整参考实现（三阶段流水线+经验回填） |

**我们的 `.kb/` 现状**：有库（目录+索引+git 版本化）无"记忆语义"——条目是自由文档，无结构化 schema、
无冲突消解、无检索评分、无自动沉淀。MEMEX 要补的就是这四块。

## 二、MEMEX 记忆体规范（设计草案 v0）

经验条目统一为 **`.kb/memory/*.yaml`**（与现有自由文档 `docs/` 并存，分工：docs=人读的知识文章，memory=机器检索的经验单元）：

```yaml
id: mem-20261029-001
type: knowhow            # knowhow（怎么做）| pitfall（坑）| preference（口径偏好）| reference（文献/文档）
scope: cut_tag           # 生效范围：产品线 / 任务类型 / 全局
task: 20261027_hook-demo # 源任务（可溯）
trigger: promoter 注释类需求   # 何时检索本条（关键词/意图）
content: >-              # 经验本体（What to do）
  promoter 口径必须与客户确认 ±N kb；默认 TSS±3kb 时要在 report 声明
evidence:                # 依据（能力 1 的"有据"要求）
  - https://...          # 文献/官方文档
  - .kb/docs/methods/xxx.md
hits: 3                  # 被检索命中并采用的次数（自学习信号）
last_verified: 2026-10-29
```

四条机制（全部来自上述借鉴）：
1. **自动沉淀**（学 claude-mem）：任务 `done` 回执时，Agent 从本次任务提取 0-N 条经验写入 memory/
2. **冲突编辑**（学 Mem0）：新经验与旧条目 `trigger` 相同且结论冲突 → 编辑旧条目并保留 `superseded` 历史，不堆副本
3. **分层检索**（学 Letta）：受理时只注入"热层"（与当前 scope 匹配、按 hits/时间排序的前 N 条）
4. **升华**（学 Hindsight）：同类 knowhow 累积 ≥3 条 → 提示 Agent 升华为 `docs/methods/` 正式方案文档

## 三、分期

| 期 | 内容 | 依赖 |
|---|---|---|
| M1 | memory/ schema + 3 条种子经验 + 受理/收尾规则接入（查库提示注入） | 零代码，纯文档+规则 |
| M2 | `ws_memory.sh add/search` 小工具（grep 评分：trigger 命中数 + hits 排序） | M1 |
| M3 | 自动沉淀：收尾回执时 Agent 按 schema 提取经验（规则固化） | M2 |
| M4 | 升华机制 + 冲突编辑 + hits 统计自动化 | M3 |
